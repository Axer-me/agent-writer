# План: одна сцена и промпты под GigaChat

15 ноября 2026. Источник: `ОЦЕНКА-И-ШАГИ-2026-11-15.md` и выбор после замера. Этот файл — ТЗ, по которому идём по шагам. Пока шаг не закрыт по разделу «Готово, когда», к следующему не переходить.

Шаги 1–7 сделаны 15 ноября 2026. Шаг 8, платный замер, не запускался.

## Что уже решено и в плане не переоткрывается

1. Один запуск пишет одну сцену. Эта сцена и есть текущая глава на экране. Кнопки остаются «Писать главу» и «Принять главу». Отдельной кнопки «закрыть главу» и сборки длинной главы из нескольких сцен в этом плане нет.
2. Ориентир 2500–5000 слов на главу на время этого плана снят. Короткая сцена, в которой есть место, имя и одно изменение, браком не считается. Возвращать длинную главу будем отдельным планом, когда одна сцена стабильно держит заказ.
3. Ближайший месяц только авторские книги. Промпты чужого канона, заметки «книги/игры/сериал» и библия франшизы в этих шагах не меняются.
4. GigaChat остаётся моделью прозы. Покупка другой модели в план не входит.
5. Новых запретных фраз в промпт не добавлять. Список «не просто», «вихрь эмоций», «стоит отметить» остаётся как есть и не расширяется.
6. План на 50 глав по-прежнему обязателен до запуска. Ослаблять эту проверку в этих шагах нельзя.
7. Уже написанные книги не перегенерировать: `ночная-кухня-3f50c0`, `мастерская-лиды-a49201`, `аудит-ведьмак-книжный-канон-505813`, «Котик и Свинка».
8. Платный замер GigaChat делается только отдельным шагом и только по просьбе. Шаги 1–7 проверяются тестами без модели.

## Порядок

1. Ножницы больше не удаляют текст.
2. Один запуск пишет одну сцену, без склейки и без дописки до 700 слов.
3. Запрет карточки дописывается в контракт кодом, дословно.
4. Промпт сцены: образец абзаца, без заказа длины и без приказа «как долго идут».
5. Пустой ответ арки всё равно оставляет окно из плана.
6. Из фактов выкидываются строки-отчёты, список не превращается в пересказ.
7. Принятая глава остаётся на экране, пока пишется следующая.
8. По просьбе — повторный замер одной ночи с одним запретом.

## Шаг 1. Ножницы больше не удаляют текст

### Зачем

15 ноября фраза «обещает вернуться через несколько недель» внутри первой сцены отрезала всё после себя. В главе осталось 567 слов из 3430. Файлы сцен на диске были целые, глава — нет.

### Как сейчас

`clip_unauthorized_time` в `app/pipeline/bounds.py` идёт по абзацам и на первом совпадении выбрасывает этот абзац и всё, что ниже. Если остаток длиннее 180 слов, `_hold_to_plan` в `app/pipeline/chapter.py` подставляет остаток вместо главы. Совпадение «несколько недель» ловит и обещание персонажа о будущем.

Принятие и так блокируется через `acceptance_block` → `plan_bound_issues`, если скачок остался в тексте.

### Сделать

1. `_hold_to_plan` возвращает исходный текст целиком. Модель для «починки» скачка не вызывается. Текст не подменяется обрезком.
2. `clip_unauthorized_time` можно оставить как функцию, но пайплайн главы её результат в черновик не пишет. Предупреждение попадает в `bounds` и показывается на экране, как сейчас показываются замечания проверки.
3. Скачком считается только повествование, которое само переносит часы:
   - месяц: как сейчас (`прошёл месяц`, `через месяц`, `спустя месяц`);
   - год: как сейчас;
   - несколько дней: как сейчас (`дни шли`, `день за днём`, `прошло несколько дней`, `через несколько дней`, `дни тянулись`);
   - неделя: `прошла неделя`, `прошёл неделю`, `недели спустя`, `спустя неделю`, `через неделю`.
4. «Несколько недель» само по себе скачком не является.
5. Если в том же предложении есть обещание (`верн`, `обеща`, `потом`, `позже`, `завтра`, `жди`), фразы `через неделю` и `через несколько недель` скачком не считаются. Пример, который должен проходить: «он обещает вернуться через несколько недель».
6. Пример, который по-прежнему считается скачком: «Прошёл месяц. Дни шли один за другим.» При этом текст остаётся целиком, а `bound_block_reason` не пустой, поэтому «Принять главу» такую главу не примет.
7. Тест `test_month_jump_is_cut_when_plan_is_one_night` переписать под новое правило: обрезка не происходит, блокировка принятия остаётся. Добавить отдельный тест на обещание «вернуться через несколько недель»: замечания нет, текст тот же.

### Готово, когда

Черновик после проверки скачка пословно равен тексту до проверки. Принятие главы с «прошёл месяц» при плане «одна ночь» по-прежнему отклоняется. Принятие текста с одним обещанием «вернуться через несколько недель» этой проверкой не отклоняется.

### В этот шаг не входит

Менять число сцен, промпты, факты, арку и экран.

## Шаг 2. Один запуск — одна сцена

### Зачем

Четыре сцены одной ночи заставили модель изобрести утро, клиента и вскрытие крышки, иначе нечем было набирать длину. Склейка потом смотрела уже на испорченные куски.

### Как сейчас

`CONTRACT_SYSTEM` просит 4–6 сцен. `generate_chapter` пишет каждую, затем `_extend_if_short` дописывает до `MIN_SCENE_WORDS` (700). Потом отдельный вызов склейки. В промпте сцены есть «Минимум около 800 слов». Если черновик уже есть, сцена пишется заново. Если черновик пуст и файлы сцен идут подряд с первой, они переиспользуются.

### Сделать

Новый порядок `generate_chapter`:

1. Черновик этой главы уже непустой: удалить файлы `chapters/NNN-scene-*.md`, заново запросить контракт и одну сцену. Старое поведение «повторный запуск заменяет непринятый черновик» сохранить.
2. Черновик пуст, контракт есть и есть `chapters/NNN-scene-01.md`: модель не звать, черновик равен этому файлу.
3. Иначе один вызов контракта и один вызов прозы.
4. Контракт просит одну сцену, не 4–6. Поля те же: место и время, участники, исходное состояние, изменение, нельзя раскрывать, концовка. Сначала блок главы, затем ровно один блок `### Сцена 1` с теми же полями.
5. Если модель вернула несколько блоков `### Сцена`, в прозу идёт только первый. Остальные в черновик не пишутся и второй вызов прозы не делается.
6. `_extend_if_short` из этого пути не вызывается. Строка «Минимум около 800 слов» из `_scene_system` удаляется. Вместо неё: «Остановись, когда произошло изменение этой сцены. Длину не набирай».
7. Вызов склейки удаляется из `generate_chapter`. Черновик равен тексту единственной сцены после вычитки.
8. Вычитка `de_llm` остаётся: без штампов модель не зовётся, короткий ответ не подменяет абзац.
9. Файл `chapters/NNN-scene-01.md` пишется до вычитки и хранит ответ модели. Черновик — то, что видит человек после вычитки и проверки. Если вычитка ничего не меняла, они совпадают.
10. Проверка места, участников, запрета контракта и мёртвых имён остаётся и смотрит полный черновик.
11. Отмена между сценами теряет смысл при одной сцене. Кнопку «Остановить» оставить: она прерывает текущий вызов, если ответ ещё не записан. Уже записанный `scene-01` при пустом черновике подхватывается правилом 2.

### Готово, когда

По коду одного запуска видно не больше двух вызовов прозы: контракт и одна сцена. Вызовов дописки и склейки нет. Тест без модели проверяет, что в системном тексте контракта нет требования «4–6», а в системном тексте сцены нет «800 слов». Существующий тест на «не подставляй дорогу» остаётся зелёным.

### В этот шаг не входит

Новый образец абзаца, запреты карточки, смена подписей кнопок, сборка нескольких сцен в одну длинную главу.

## Шаг 3. Запрет карточки попадает в контракт дословно

### Зачем

В замере карточка говорила «не выходит из мастерской». Контракт пересказал это как «утро, всё ещё в мастерской, готовится встретить клиента». Проза писала контракт. Проверка «два слова из поля „нельзя“ нашлись в тексте» для такого запрета не годится: слова «Лида» и «мастерская» есть и в верной сцене, где она никуда не ушла.

### Сделать

1. Функция читает `card.md` и забирает предложения, в которых есть одно из: `нельзя`, `не выходит`, `не выход`, `не открыва`, `не покид`, `остаётся в`, `остается в`. Предложение — кусок от границы `.`, `!`, `?` или новой строки до следующей такой границы.
2. После ответа модели эти предложения дописываются в конец контракта отдельным блоком, даже если модель уже что-то написала в «Нельзя раскрывать»:

```
Запрет карточки:
- <предложение из карточки дословно>
```

3. Блок попадает и в файл `chapters/NNN-contract.md`, и в задание прозы.
4. `contract_issues` по-прежнему проверяет только поле «Нельзя раскрывать» в шапке контракта, до первого `###`. Блок «Запрет карточки» этой проверкой не читается. Автоматического детектора «герой вышел из комнаты» не делать.
5. Если в карточке таких предложений нет, блок не добавляется и контракт не меняется.

### Готово, когда

Тест без модели: карточка с фразой «В первой главе она не выходит из мастерской.» даёт контракт, где эта фраза есть целиком. Та же фраза в поле «Запрет карточки» не создаёт замечание `contract_issues`, если в тексте есть слова «Лида» и «мастерская».

### В этот шаг не входит

Пытаться кодом доказать, что герой нарушил запрет. Это читает человек на экране.

## Шаг 4. Промпт сцены под GigaChat

### Зачем

Модель держит близкий приказ и пример. Длинный устав и заказ длины она обходит: запретных штампов в замере не было, а текст был гладкий. Строка «нужны путь, быт, как долго идут» в общем правиле прозы спорит с правилом «дорогу не добавляй».

### Сделать

1. В `CONTRACT_SYSTEM` один заполненный пример на три-четыре строки правильным русским, до пустого шаблона. Пример про одну ночь и одну комнату, без дороги. Поля примера не противоречат друг другу: если в «нельзя» сказано не открывать предмет, в «изменении» нет его вскрытия.
2. В `_scene_system` перед запретами стоит короткий образец абзаца на 60–90 слов: рука, один предмет, одна деталь, короткая фраза рядом с длинной, без морали в конце. Образец помечен как образец ритма, не как сюжет книги. Сюжет образца не про часы и не про кухню, чтобы модель не тащила его в чужую книгу. Подойдёт человек, который чинит застёжку ремня за столом.
3. Из `HUMAN_PROSE` уходит предложение про путь, быт, паузы, тело, погоду и «как долго идут». На его месте: «Пиши действие и одну конкретную деталь места или предмета. Быт только тот, который есть в задании этой сцены.»
4. Хвост запретов в `HUMAN_PROSE` остаётся тем же списком, без новых пунктов.
5. `KEEP_LENGTH` остаётся запретом сокращать уже написанное при вычитке и правке фрагмента. В промпте новой сцены его не использовать как приказ писать длиннее.
6. Правило первой сцены первой главы сохранить: не начинать с «ты кто?», не начинать с боя, которого нет в плане, не добавлять дорогу, если её нет в замысле.
7. Снимок `промпты_книги.py` обновить теми же текстами. Приложение его по-прежнему не исполняет.

### Готово, когда

Тест собирает системный текст сцены и контракта и проверяет: есть образец, нет «800 слов», нет «как долго идут», есть «не подставляй дорогу». Новый запретный штамп в список не добавлен.

### В этот шаг не входит

Второй проход «перепиши красивее». Вычитка штампов остаётся как была.

## Шаг 5. Пустая арка заполняется из плана

### Зачем

После принятия «Мастерской Лиды» таблица `arc_windows` была пуста. `fill_arc_from_plan` подставляет обещание из «ещё рано» только если разбор ответа уже вернул словарь. Пустой или неузнанный ответ выходит раньше и окно не пишет.

### Сделать

1. В промпт `refresh_arc` добавить три строки-образца и попросить держаться этого вида:

```
Обещание: кто оставил вещь, ещё рано
Выплата не раньше главы: 6
Глава 2: герой остаётся на месте и не открывает вещь
```

Образец помечен как образец формата. Имена из него в книгу не переносить, если их нет в карточке и плане.

2. Если `_parse_arc` вернул `None` или пустое обещание, всё равно собрать окно через `fill_arc_from_plan` для глав от текущей до текущая+4, не дальше 50.
3. Если после этого обещание всё ещё пустое, записать «Раскрытие этой линии ещё рано.» Выплату поставить на конец окна, как `fill_arc_from_plan` уже делает для нуля.
4. Второй вызов модели при пустом ответе не делать.
5. Успешный разбор с непустым обещанием не затирать запасным текстом.

### Готово, когда

Тест без модели вызывает путь «ответ пустой» на плане, где у главы есть «ещё рано», и в `arc_windows` появляется это обещание. Отдельный тест: нормально разобранное обещание «письмо не вскрывать» остаётся, а не заменяется фразой плана.

### В этот шаг не входит

Новые типы событий. Четыре вида `решение|рана|уход|знание` остаются.

## Шаг 6. Факты не становятся пересказом

### Зачем

В замере в факты попали строки «Деньги: нет упоминания о финансах», «Утро начинается», «Возвращение в мастерскую». Следующая глава получила бы нарушение карточки уже как память.

### Как сейчас

Промпт просит 20–40 строк. `fact_lines` принимает маркированные строки и любые фразы длиной 12–220 знаков, до 40 штук. Пустой разбор старый список не стирает. Это сохранить.

### Сделать

1. Промпт просит не больше шести строк о том, что изменилось в этой сцене, плюс старые строки, которые всё ещё верны. Просит не писать, чего в тексте не было.
2. Перед записью выкинуть строку, если в ней есть `нет упомина`, `не упомина`, либо она начинается с ярлыка схемы: `Деньги:`, `Рана`, `Где кто:`, `Окончание главы:`, `День/время`.
3. Потолок хранения 40 строк остаётся.
4. Если после отсева список пуст, старые факты не стирать. Это уже делает пустой разбор; отсев, который выкинул всё, считать пустым разбором.

### Готово, когда

Тест: строка «Деньги: нет упоминания о финансах» не сохраняется. Строка «Лида в мастерской, крышка закрыта.» сохраняется. Ответ только из выкинутых строк оставляет прежние факты на месте.

### В этот шаг не входит

Проверка, что факт не противоречит последнему абзацу. Это отдельная задача, в этот план не входит: детектор противоречия легко примет верную сцену за ошибку.

## Шаг 7. Принятая глава видна на экране

### Зачем

Сейчас `accept_chapter` увеличивает `chapter_number`, а редактор показывает `draft` новой главы. После принятия экран пустой, хотя `chapters/NNN.md` уже записан.

### Сделать

1. `public_dict` отдаёт поле `accepted_text`: текст `chapters/(номер-1).md`, если черновик текущего номера пуст и номер больше 1. Иначе пустая строка.
2. На этапе главы над редактором постоянный блок с этим текстом. Редактор по-прежнему связан только с черновиком текущего номера.
3. Автосохранение и «Сохранить» пишут только редактор. Текст из блока принятой главы в черновик следующей не копируется.
4. Когда генерация следующей главы начала писать черновик, блок принятой главы остаётся, чтобы было с чем сверить.
5. Подписи кнопок не менять.

### Готово, когда

В браузере на книге с уже принятой главой и пустым черновиком следующей виден текст принятой главы, поле черновика пустое, сохранение страницы не создаёт черновик из этого текста. Проверять на тестовой книге, не на «Мастерской Лиды» и не на книгах из пункта 7 решений в начале файла. Если удобной тестовой книги нет, создать короткую локально, без вызова модели: записать `chapters/001.md` вручную и выставить `chapter_number` 2.

### В этот шаг не входит

Новый редактор, экспорт, правки вёрстки вне этого блока.

## Шаг 8. Повторный замер

Делать только по отдельной просьбе, после закрытых шагов 1–7.

Книга новая, авторская, не из списка уже написанных. Карточка: имя, место, одно желание, один запрет вида «в этой главе не выходит из комнаты» и «не открывает предмет». План на 50 строк можно собрать локально, как в замере 15 ноября. Один запуск.

Смотреть руками:

- в черновике одна сцена, число слов совпадает с файлом сцены после вычитки, обрезка не случилась;
- запрет карточки есть в контракте дословно;
- если модель нарушила запрет, текст всё равно цел и виден, а не обрезан;
- после принятия окно арки непустое;
- в фактах нет строки «нет упоминания».

Успех замера — хочется ли читать следующую страницу. Доля зелёных проверок успехом не считается.

## Что после этого плана не делать само собой

- Редактор, EPUB, DOCX, установщик.
- База чужого канона и правка ведьмачьей библии.
- Сборка одной главы из нескольких принятых сцен ради объёма 2500–5000.
- Новый список запретных фраз.
- Ослабление требования «план 1–50 до запуска».
