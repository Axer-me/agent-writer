# Ход проекта: Агент-писатель

Каноническая память проекта. Агент читает этот файл в начале работы и обновляет после решений и завершённых шагов. Не стенограмма чатов — сжатый контекст без потери фактов.

## Цель

Локальный агент-писатель: **оригинал** или **чужая вселенная** (пример: Ведьмак) с **новыми поворотами событий**. Только чтобы было что почитать себе; **продавать нельзя** (чужой IP).

MVP: **~50 глав**, готовый текст **только по-русски** (английские произведения — после MVP). **1 запуск = 1 глава.** Объём главы **ориентир 2500–5000 слов**, не брак, если чуть меньше/больше. Контент может быть **18+**; **цензуры в продукте нет и не делать**. Проза должна читаться как **живой автор**, не как нейросеть: избегать всего, по чему текст выдаёт LLM.

Если пользователь дал жанр, POV, синопсис, рейтинг, канон/AU и т.п. — **следовать**. Если не дал — агент **сам предлагает** на одобрение, с перегенерацией.

## Сейчас

- MVP собран: локальный UI, пайплайн карточка → библия → план → глава. Код: https://github.com/Axer-me/agent-writer (секреты и книги в git не входят).
- Запуск: `run.bat` → `http://127.0.0.1:8765` (watch только каталог `app/`, не `projects/` — иначе запись главы срывает reload и файл остаётся пустым).
- Ключи: `OPEN_ROUTER_API_KEY`, `GIGACHAT_API_KEY` (длинный **ключ авторизации** base64, не Client ID). SSL Сбера: `GIGACHAT_VERIFY_SSL=false`.
- **Главы: GigaChat.** OpenRouter только `:free`; при 429/ошибке лор/план/стиль **падают на GigaChat**, иначе пайплайн стоит (лимит :free ~50/день, во время разработки уже ловили 429).
- Эмбеддинги: `intfloat/multilingual-e5-small`, порог похожести **0.92** (на CPU; 3060 в этом окружении torch без CUDA). Selftest: парафраз ~0.99, другая сцена ~0.84.
- Объём: пайплайн дописывает короткие сцены (порог ~700 слов), склейка/анти-LLM откатываются, если модель сжала текст. Старый прогон ~500–700 слов без этого пакета.

## Артефакты и пайплайн одной книги

Порядок:

1. **Карточка** — оригинал / вселенная, синопсис, канон или AU, POV, прочее. Пустое → предложение агента → утверждение.
2. **Вселенная (не оригинал)** — изучить заданный лор; результат: полная **библия**.
3. **Стиль (опционально)** — если есть ссылка на другое произведение (или файлы): вычленить манеру автора.
4. **План** — общий план под синопсис, **что происходит в ближайших 50 главах** (`plan.md`) → утверждение с комментариями.
5. **Таймлайн + факты** — якоря времени/места; детали вроде денег ГГ — да, но коротко.
6. **Цикл главы** — черновик → проход «убрать нейросетевой налёт» → проверка повторов → показ пользователю → правка кусков или «ок» → финал → обновление памяти → опциональная корректировка курса (пусто = агент сам по плану).

**Библия (`bible.md`):** все **главные и второстепенные** персонажи: описание, роль в **основном сюжете вселенной**, статус (жив / мёртв / ушёл). Агент может сам закрыть участие и записать; пользователь оспаривает — запись меняется.

**Стиль (`style.md`):** до **10 длинных фрагментов** (не коротких цитат). Источники: попытка снять с URL (**ориентиры:** [tl.rulate.ru](https://tl.rulate.ru/), [forum.questionablequesting.com](https://forum.questionablequesting.com/)); опционально **куки**; если сайт не отдаёт — пользователь грузит **до 10 файлов txt/docx/pdf**. Дополнительно: **известные факты о манере автора**, не только сырой текст. В файл — черты стиля (ритм, лексика, приёмы), не зеркало чужой книги. На парсер **не тратить много времени**.

**План:** пользователь утверждает; комментарий → перепись плана с учётом комментария. Позже в пунктах плана — **теги сцен** (засада, торг, разговор у костра…), чтобы ловить слишком частые одинаковые **ходы** (это уже после MVP-антиповтора формулировок).

## Непрерывность сюжета

- Каждая глава — **логическое продолжение предыдущей**; контекст не терять; **сюжет не повторять** (отслеживать).
- В промпт **не класть все 50 глав**. Класть: срез плана, саммари уже произошедшего, **1–2 последние главы полностью**, карточки **активных** персонажей (не весь каст), сжатые факты.
- **Пропажа персонажа (подсказка, не автомат):** жив, нет логичной причины выйти из сюжета, долго нет (ориентир **30 глав**) → спросить пользователя: задействовать в ближайших **~20 главах** или объяснить отсутствие. Жёсткий автовозврат запрещён — получается вымученно.
- **Факты:** отдельный короткий список (~20–40 строк: деньги, раны, где кто). После каждой главы — маленький проход «что изменилось», не раздувать контекст.
- **`last_seen`** персонажей в машинном состоянии.

## Живой текст (не «как нейросеть»)

Готовые главы — **максимально похожи на человека**. Если есть `style.md` — он главнее общих правил. Если стиля нет — всё равно не писать «нейросетевым» русским.

Гнать и вычищать типичные следы LLM, в том числе:

- ровные абзацы одной длины, тройки «не просто X, а Y», мораль сцены в конце;
- объявление эмоций и темы в лоб («он почувствовал смесь…», «это изменило всё»);
- канцелярит, кальки, пустые метафоры («вихрь эмоций», «ткань реальности»);
- герои, которые объясняют сюжет репликами; одинаковый ритм всех предложений;
- слова-паразиты эссе: «стоит отметить», «важно понимать», идеально вежливые резюме.

Нужны неровный ритм, конкретные детали, характеры в поступках и речи, а не в подписях к чувствам. Это **жёсткое требование к прозе**, не пожелание. В цикле главы — отдельный проход вычитки под это, до показа пользователю.

## Глава: черновик, объём, антиповтор

- Объём — ориентир, не контракт. Одна глава **не одним** вызовом модели: сцены → несколько кусков прозы → склейка → проход логики/деталей → **анти-LLM вычитка**.
- Сначала **черновик**. Пользователь может отправить на доработку **отдельные абзацы/куски**; целиком главу без нужды не переписывать — иначе новые противоречия.
- **До показа пользователю:** (1) живой текст / анти-LLM, (2) повтор **одних и тех же сцен и формулировок** (векторы кусков vs уже сохранённые). Позже — ещё частота одинаковых сюжетных поворотов.
- После главы пользователь может сменить направление истории или молчать.

**Канон:** всегда стараться держаться канона, **пока пользователь не сказал обратное** (AU на его усмотрение). Модель всё равно будет галлюцинировать лор — библия и правки пользователя важнее «памяти модели про Ведьмака».

## Стек и хранение

UI → оркестратор этапов → провайдер LLM → папка книги. Абстракция провайдера, чтобы сменить модель без переписи пайплайна.

| Слой | Выбор | Почему / отвергли |
|------|--------|-------------------|
| UI MVP | Браузер на `localhost` (не установщик .exe) | Пользователь так выбрал; CLI-only не нужен |
| Бэкенд (договорённость с архитектуры) | Python + простой локальный веб (FastAPI + страница) | Быстрый MVP под LLM/файлы; десктоп позже |
| Книги | Несколько произведений, каталог `projects/` | Не один активный файл |
| Главы | **GigaChat** (токены пользователя); запас **OpenRouter `:free`** при цензоре | На OpenRouter нет денег. 18+ часто режет GigaChat PERS |
| OpenRouter | Только slug с `:free`, дефолт `z-ai/glm-5.2:free`. Не `openrouter/free` | Платные модели дадут 402 |
| Эмбеддинги | Локально (маленькая мультиязычная, 3060 или CPU); API — запас | Пользователь хотел API из сомнения в ПК; по железу локально ок |
| Сеть | Обязательна: модели + ссылки | Офлайн-MVP нет |
| Папка книги | Проза/лор — **`.md`**; счётчики, last_seen — **`state.json`**; векторы абзацев — **SQLite** рядом | Три памяти: человеку читать, машине считать, антиповтор искать. Не «всё в одной векторной БД», не отдельный Chroma на MVP |

Файлы книги: `bible.md`, `plan.md`, `style.md`, `timeline.md`, факты, `state.json`, `chapters/` (черновик + финал), sqlite эмбеддингов.

**Право:** личный фанфик ок; скрейпер — best-effort HTML, не качалка библиотеки переводов.
